\chapter{Conexiones UDP y TCP}

El servidor DNS implementado usa la librería \texttt{tokio} para atender consultas en UDP y TCP de forma asíncrona y concurrente. 
Además de la funcionalidad básica de recibir y devolver respuestas, también soporta EDNS0, detecta y respeta el payload (tamaño del mensaje) máximo 
anunciado por el cliente en el registro \texttt{OPT}, maneja el estándar DNSSEC (lectura del bit DO) y protege operaciones críticas
con timeouts para evitar bloqueos y bucles infinitos. También se manejan correctamente errores de parseo (se responde FORMERR) y
se implementa el comportamiento para truncamiento (TC) sobre UDP con fallback a TCP.

A continuación se describen las implementaciones específicas para cada protocolo.

%%Explicacion de los campos

El campo \texttt{timeout} define el tiempo máximo que el servidor esperará para recibir una consulta o enviar una respuesta antes de abortar la operación.
El campo \texttt{payload\_size} establece el tamaño máximo de la consulta DNS que el servidor puede procesar.

%%Explicacion de los metodos

Los métodos definidos incluyen funciones típicas como \texttt{new} y \texttt{new\_default}, que permiten crear 
una instancia de la clase con parámetros personalizados o por defecto. Sin embargo, la función más relevante es \texttt{receive\_and\_response}, 
la cual se encarga de recibir y responder de manera asíncrona a las consultas DNS enviadas por los clientes. Además esta función tiene en cuenta el tamaño maximo que puede soportar
el servidor al momento de recibir consultas UDP, ya que si el tamaño de la consulta excede el \texttt{payload\_size} se activa el bit TC en la respuesta para que el cliente reintente la consulta por TCP.

%%Explicación del flujo

La funcion \texttt{receive\_and\_response} sigue los siguientes pasos:
\begin{itemize}
    \item Crea un socket UDP y se enlaza a localhost en el puerto 53.
    \item Entra en un bucle infinito donde se espera recibir consultas DNS.
    \item Crea threads con \texttt{tokio} para manejar cada consulta de forma concurrente.
    \item En cada thread, si el tamaño de la consulta es mayor al \texttt{payload\_size}, se usa la función \texttt{handle\_dns\_message\_udp\_with\_timeout}
          con \texttt{tc\_case} en verdadero, de lo contrario se llama a la misma función con \texttt{tc\_case} en false. \texttt{tc\_case} indica si se debe manejar el caso de truncamiento (TC).
\end{itemize}

Con respecto a la función auxiliar \texttt{handle\_dns\_message\_udp\_with\_timeout}, esta se encarga de:

% Personalizar bullets de todos los niveles
\setlist[itemize,1]{label=$\bullet$}
\setlist[itemize,2]{label=--}
\setlist[itemize,3]{label=--}
\setlist[itemize,4]{label=--}



\begin{itemize}
    \item Parsear el \textbf{Header DNS}, correspondiente a los primeros 12 bytes del buffer recibido.  
    \item Intenta parsear el \textbf{mensaje DNS completo} bajo un \texttt{timeout}.
    \begin{itemize}
        \item Si falla el parsing, responde con un \texttt{RCODE=FORMERR}.
        \item Si expira el timeout, devuelve un error de timeout.
    \end{itemize}

    \item Si \texttt{tc\_case} es verdadero:
    \begin{itemize}
        \item Clona el mensaje original.
        \item Activa el bit \texttt{TC} en el header de respuesta.
        \item Reenvía el mensaje original truncado al cliente.
        \item Termina la ejecución.
    \end{itemize}

    \item Si no es un TC case, busca si el mensaje contiene un registro \texttt{OPT} (EDNS0):
    \begin{itemize}
        \item Si hay algún \texttt{OPT}, obtiene el \textbf{DO bit} desde el campo TTL.
        \item Dependiendo del DO bit:
        \begin{itemize}
            \item Si está activo, llama a \texttt{lookup\_data} con \texttt{dnssec=true}.
            \item Si no está activo, llama a \texttt{lookup\_data} con \texttt{dnssec=false}.
        \end{itemize}
        \item Transforma la respuesta en bytes.
        \item Compara el tamaño de la respuesta con el valor de \texttt{UDP payload size} del registro OPT.
        \begin{itemize}
            \item Si la respuesta es mayor al tamaño permitido por el cliente:
            \begin{itemize}
                \item Marca el TC bit en la cabecera original.
                \item Responde con la versión truncada.
            \end{itemize}
            \item Si cabe dentro del tamaño permitido:
            \begin{itemize}
                \item Envía la respuesta completa.
            \end{itemize}
        \end{itemize}
    \end{itemize}

    \item Si no hay EDNS0 (sin registro OPT):
    \begin{itemize}
        \item Llama a \texttt{lookup\_data} con \texttt{dnssec=false}.
        \item Envía la respuesta al cliente.
    \end{itemize}
\end{itemize}

\section{TCP}

El servidor TCP está implementado en la estructura \texttt{ServerTCPConnection}, que contiene los siguientes campos y métodos:

\begin{tabular}{|p{0.95\linewidth}|}
\hline
\multicolumn{1}{|c|}{\textbf{ServerTCPConnection}} \\
\hline
\textbf{Campos} \\
\hline
\texttt{- timeout: tokio::time::Duration} \\
\texttt{- payload\_size: usize} \\
\hline
\textbf{Métodos Públicos} \\
\hline
\texttt{+ new(timeout: Duration, payload\_size: usize)\ \ ->\ Self} \\
\texttt{+ new\_default(timeout: Duration)\ \ ->\ Self} \\
\texttt{+ get\_timeout(self: Self)\ \ ->\ tokio::time::Duration} \\
\texttt{+ receive\_and\_response(\&self)\ \ ->\ Result<(), ServerError>} \\
\hline
\textbf{Métodos Privados / Auxiliares} \\
\hline
\texttt{- handle\_dns\_message\_with\_timeout(} \\
\texttt{\ \ timeout\_server: Duration, recv\_buf: \&[u8],} \\
\texttt{\ \ socket: \&mut TcpStream )\ \ ->\ Result<(), ServerError>} \\[0.3em]
\texttt{- handle\_connection(} \\
\texttt{\ \ timeout\_server: Duration, socket: TcpStream,} \\
\texttt{\ \ addr: std::net::SocketAddr )\ \ ->\ Result<(), ServerError>} \\
\hline
\end{tabular}


La versión TCP del servidor comparte gran parte de su estructura con el modo UDP, ya que utiliza los mismos campos principales y métodos similares para la configuración y el procesamiento de consultas.

La principal diferencia radica en la función \texttt{handle\_connection}, la cual se encarga de gestionar cada conexión TCP entrante. Esta función primero lee un prefijo de 2 bytes que indica
la longitud total del mensaje DNS (requisito del protocolo cuando se utiliza TCP) y, a continuación, recibe el mensaje completo. Una vez obtenido, delega su procesamiento a la función 
\texttt{handle\_dns\_message\_with\_timeout}.

En este caso la funcion \texttt{handle\_dns\_message\_with\_timeout} no necesita manejar el caso de truncamiento (TC), ya que TCP garantiza la entrega completa del mensaje. Además es 
practicamente identica a la vista en UDP pero con la diferencia que antes de mandar el mensaje final (sea el caso que sea) debe anteponer el prefijo de 2 bytes con la longitud del mensaje a enviar.
